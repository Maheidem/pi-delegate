# delegate — P1/P2/P3 fix plan (2026-09-02)

Goal: a1d66100-0192-4c8e-8ebb-e1c941b7aa25
Baseline: 0.1.4 @ 920c5d7 (clean tree)

## Evidence (from live goal session 17-18-47, 34 runs, 5.78h)

- 28 succeeded / 3 timed_out_idle / 1 timed_out_hard / 1 cancelled; $2.88 total,
  $0.33 (11%) burned in timeouts + recovery re-delegations.
- Runs `del_20260902T171941Z_0d88351d` (101s) and `del_20260902T173809Z_7f30d98c`
  (565s): parent session has `succeeded` tool results with full handoffs; on-disk
  metadata says `crashed` / `E_ORPHANED_RUN`, and the `finishedAt` stamps
  (17:20:38, 17:46:35) equal the start times of *other* pi processes.

## Root cause (verified)

1. `markOrphanedRuns` (run-store.ts) marks every non-terminal run crashed at pi
   startup with **no PID liveness check**, even though `pid` is stored in metadata.
2. The true `succeeded` finalization is then rejected by the terminal-immutability
   guard (run-store.ts, `updateRunMetadata`) — by design, protecting the wrong state.
3. Net: the evidence store lies for exactly the multi-session pattern in AGENTS.md.

## Changes

### P1 — orphan recovery must respect live pi PIDs (run-store.ts)

- `isPidAlive(pid)`: `process.kill(pid, 0)`; ESRCH/EINVAL → dead; EPERM → alive.
- `pidCommandLineIsPi(pid)`: read cmdline via `/proc/<pid>/cmdline` (NUL-separated,
  Linux) or `ps -o args= -p <pid>` (macOS/other); true iff some whitespace-split
  token's path basename is exactly `pi` (matches `pi --mode rpc ...`,
  `node /opt/homebrew/.../pi ...`, and the compiled-executable case).
- `markOrphanedRuns` decision table (per non-terminal run):
  | stored pid | liveness | cmdline | action |
  |---|---|---|---|
  | absent | — | — | mark crashed (unchanged) |
  | present | dead | — | mark crashed (unchanged) |
  | present | alive | contains `pi` token | **skip** (live delegate child) |
  | present | alive | known, no `pi` token | mark crashed (recycled PID; message notes liveness check) |
  | present | alive | unreadable | **skip** (fail-safe; message n/a — left nonterminal, doctor can flag) |
- Message for the recycled-pid mark keeps `E_ORPHANED_RUN` with the note
  "pid <N> alive but not a pi process (recycled pid)".
- Signature unchanged (`agentDir`); `application.markOrphansOnStartup` unchanged.

### P3 — timeout/cancel terminal states carry error payloads (runner.ts)

`finish(state, error?)` synthesizes (only when no error passed AND state is
timed_out_idle / timed_out_hard / cancelled):
- `timed_out_idle` → `{ code: "E_TIMEOUT_IDLE", message: "no child activity for <dur> (inactivity watchdog)" }`
- `timed_out_hard` → `{ code: "E_TIMEOUT_HARD", message: "hard timeout of <dur> reached (wall-clock cap)" }`
- `cancelled` → `{ code: "E_CANCELLED", message: cancelledByUser ? "cancelled by user" : "aborted (parent session abort)" }`
- `<dur>` via `formatDuration(cfg.*)`. Covers every path because all of
  `armInactivity`/`hardTimer`/`cancel()`/`finalizeOnExit`/`finalizeSettled`
  funnel through `finish`. Flows into `outcome.error` (tool text + `details`)
  and metadata `errorCode`/`errorMessage`. `succeeded`/`failed` states unaffected.

### Curation — the clobbered runs (scope expanded at execution time)

At execution time (2026-09-03) the store had suffered a second, independent
data-loss event: `enforceRetention` (default `maxRuns: 50`) ran at a pi startup
(2026-09-03T03:40:59Z) and removed the 9 oldest terminal receipts —
metadata + transcript + stderr — including both clobbered runs. So curation
reconstructed **9 receipts** from the parent sessions' delegate tool results
(authoritative: exact state, timestamps, usage, stopReason, outputBytes,
outputTruncated, handoff text) and corrected **8 more** receipts that
finalized under 0.1.4 without an error payload:

- 9 reconstructed (via `.planning/curate-runs.mjs`): 7× succeeded from the
  goal session (incl. `0d88351d`, `7f30d98c`), 1× succeeded from the 00:58
  e2e session, 2× crashed spawn-failures from the 13:58 session
  (older pi build: `--mode` rejected, exit 1).
- 2× `E_CHILD_EXIT` with the verbatim error text from the tool results
  (the two reconstructed crash receipts).
- 6× live receipts: `E_TIMEOUT_IDLE` ×4 (messages derived from the in-effect
  timeout config at run time — 5m default ×3, 22m30s = 45m-project/2 cap ×1),
  `E_TIMEOUT_HARD` ×1 (45m project cap, wall 2702s), `E_CANCELLED` ×1.
  (via `.planning/curate-runs-part2.mjs`)
- `del_20260902T181850Z_9da48e0b`: clobber raced the hard-timeout finalization
  6 ms apart (clobber 18:48:52.857Z, true write 18:48:52.863Z) leaving a mixed
  state (`timed_out_hard` + `E_ORPHANED_RUN`). Corrected to `E_TIMEOUT_HARD`.
- Every repaired receipt carries a `curationNote` recording the event and the
  source of truth; new `curationNote?: string` field on `RunMetadataV1`
  (backward compatible). Transcripts of the 9 were unrecoverable (deleted).

Verification (post-curation): 59 store runs = 59 detailed tool results, 0 state
mismatches, 0 `E_ORPHANED_RUN` with a succeeded tool result, 0 terminal failure
receipts without an error code, 0 terminal receipts without `finishedAt`,
all files 0600. The 9 reconstructed receipts carry fresh mtimes, so the next
retention sweep (oldest-mtime first) cannot hit them first.

- Scenario D proves P1 by continuous 250 ms polling: a clobber is terminal
  and permanent, so *ever* seeing `crashed` = regression; post-fix the run
  must reach `succeeded` untouched.
- Scenario F proves P3 on a real child: 15 s inactivity in the E2E agent
  config + a child running `sleep 60` → real watchdog fire.
- Residual (documented, accepted): a clobber in the sub-second window between
  the child's death and the owner's final write can still race (the exit
  handler and a startup clobber in the same event-loop turn). P1 shrinks the
  clobber window from a run's entire lifetime (minutes–hours — the observed
  bug) to the finalization tail; curation + `curationNote` remain the
  recovery path for any future straggler.

## Acceptance criteria

1. `markOrphanedRuns` never clobbers a run whose stored pid is alive and is a pi
   process — proven by e2e D (fails pre-fix, passes post-fix).
2. Timeouts/cancels surface a specific error line (never `unknown failure`) —
   proven by unit tests + e2e F on a real child.
3. Project base timeout persisted at 2h; effective idle ≥ 20m — file contents +
   cascade verification + e2e E.
4. All clobbered/lost receipts restored or corrected with true usage/handoff;
   clobber events recorded; no E_ORPHANED_RUN run with a succeeded tool
   result; every terminal failure receipt carries an error code.
5. 0.1.5 published + installed; plan doc persisted in `.planning/` (excluded from
   the npm tarball by the `files` allowlist).
